# 과거 뉴스 RAG 검색 품질 검증

> 프로젝트 종료 후 회고 차원에서 진행한 평가입니다. (2026.10, 정유진)

## 배경

STEP2 `fetch_related_news`([`STEP2/rag_search.py`](../STEP2/rag_search.py))는 현재 뉴스와 관련된 과거 뉴스를 ChromaDB에서 검색해 인사이트 생성에 사용합니다.
개발 당시 "유사도가 너무 높으면 단순 중복 기사만 나온다"는 문제를 해결하려고 아래 조건으로 결과를 걸렀습니다.

```python
if 30 <= int((1 - score) * 100) <= 75
```

이 평가에서는 다음 세 가지를 확인했습니다.

1. 이 "유사도 %"는 실제로 무엇을 의미하는가?
2. 구간 필터가 검색 품질을 실제로 개선했는가?
3. 품질 문제의 근본 원인은 무엇이며, 어떻게 개선할 수 있는가?

## 1. 지표 정의 검증 — "유사도 %"는 코사인 유사도가 아니었다

| 확인 항목 | 결과 |
|---|---|
| 컬렉션 거리 방식 | `l2` (`Chroma.from_documents` 기본값, cosine 지정 없음) |
| 임베딩 정규화 | 질의·문서 모두 길이 1 |
| 반환 `score` | 제곱 L2 거리 = `2 − 2·cos` (실데이터로 일치 확인) |
| 코드의 "유사도 %" | `(1 − score) × 100` = **`(2·cos − 1) × 100`** |

→ "유사도 30\~75%"는 실제로 **코사인 0.65\~0.875** 구간이었습니다.
정규화된 임베딩이라 검색 순위는 코사인과 동일하지만, 임계값의 의미는 개발 당시 생각과 달랐습니다.

## 2. 구간 필터의 효과 (LLM 판정)

현재 뉴스 40건 × 과거 뉴스 상위 10건 = 400쌍을 `openai/gpt-5.4-mini`로 판정했습니다.

- **duplicate**: 같은 사건을 다룬 기사
- **context**: 같은 아티스트·작품의 다른 사건 (배경 정보가 됨)
- **unrelated**: 관련 없음

**판정 신뢰도**: 20쌍을 다른 회사의 LLM(Claude)이 독립적으로 판정해 비교한 결과, **일치율 95%, Cohen's κ = 0.77**.

**코사인 구간별 분포**

| 코사인 구간 | context | duplicate | unrelated | 건수 |
|---|---|---|---|---|
| 0.65–0.75 | 0% | 0% | 100% | 14 |
| 0.75–0.80 | 33.3% | 0% | 66.7% | 9 |
| 0.80–0.85 | 13.6% | 0% | 86.4% | 44 |
| 0.85–0.875 | 0% | 0% | 100% | 8 |
| 0.875–0.90 | 7.9% | 0% | 92.1% | 38 |
| 0.90–1.00 | 0.7% | 1.0% | 98.3% | 287 |

**정책 비교 (사용자에게 보이는 상위 3건 기준)**

| | 필터 없음 | 코드 30~75% | cos 0.75~0.875 | cos ≥ 0.875 |
|---|---|---|---|---|
| 중복률 | 2.5% | 0% | 0% | 3.0% |
| 맥락 연결률 | 4.2% | **10.0%** | 13.0% | 2.0% |
| 무관 비율 | 93.3% | 90.0% | 87.0% | 95.0% |
| **결과 0건 질의** | 0% | **75.0%** | 77.5% | 15.0% |

**관찰**

- 원래 우려했던 "중복 기사" 문제는 이 데이터에서 거의 나타나지 않았습니다 (400쌍 중 1%).
- 구간 필터는 맥락 연결률을 4.2% → 10.0%로 높였지만, **질의의 75%에서 과거 뉴스를 하나도 보여주지 못했습니다.**
- 상위 결과의 72%가 코사인 0.9 이상이었지만 그중 98%가 무관했습니다. **점수 자체가 관련성을 구분하지 못하는 상태**였습니다.

## 3. 근본 원인 분석 — 커버리지와 변별력 분리

뉴스는 실시간으로 바뀌기 때문에, 과거 데이터에 관련 기사가 애초에 없는 경우가 많습니다. 그래서 "검색이 못 찾은 것"과 "찾을 게 없던 것"을 분리해 평가했습니다.

**근사 정답**: 현재 뉴스와 과거 뉴스의 `artist_tags`가 하나라도 겹치면 "관련 후보"로 간주

**커버리지**: 현재 뉴스 341건 중 같은 아티스트의 과거 기사가 존재하는 비율 = **22.6%** (77건)

**지표**

- **Hit@3**: 관련 기사가 있는 77건 중, 상위 3건 안에 같은 아티스트 기사를 찾은 비율
- **쌍 단위 AUC**: 유사도 점수가 같은 아티스트 기사를 얼마나 위로 올리는지 (0.5 = 무작위)
- **Top1 AUC**: 1등 점수만으로 "관련 기사 있음/없음"을 구분할 수 있는지 (임계값 필터의 가능성)

**임베딩 설정 비교**

| | arctic-embed-m (서비스 그대로) | arctic + 질의 접두어 | multilingual-e5-base |
|---|---|---|---|
| Hit@3 | 33.8% | 44.2% | **68.8%** |
| 쌍 단위 AUC | **0.538** | 0.780 | **0.841** |
| Top1 AUC | **0.492** | 0.642 | **0.832** |
| Top1 코사인 평균 (관련 있음 / 없음) | 0.918 / 0.926 | 0.367 / 0.333 | 0.837 / 0.811 |

## 결론

1. **근본 원인은 구간 설정이 아니라 임베딩 모델이었습니다.** 서비스에서 쓴 `Snowflake/snowflake-arctic-embed-m`은 영어 중심 모델이고, 질의 접두어 없이 사용되고 있었습니다. 그 결과 한국어 뉴스에서 점수 변별력이 무작위 수준(AUC 0.54)이었고, 어떤 임계값으로도 "관련 없음"을 걸러낼 수 없었습니다.
2. **질의 접두어 한 줄**만 추가해도 AUC가 0.54 → 0.78로 개선됩니다.
3. **다국어 모델로 교체**하면 Hit@3가 33.8% → 68.8%로 2배가 되고, Top1 AUC 0.83으로 임계값 기반 필터링이 가능한 수준이 됩니다.
4. **임계값은 모델별로 재보정해야 합니다.** 접두어 추가만으로도 코사인 분포가 크게 바뀌므로(평균 0.75 → 0.25), 기존 30~75% 구간을 그대로 쓸 수 없습니다.

## 한계

- "같은 아티스트 = 관련"은 근사 기준입니다. 이름만 겹치고 내용은 무관한 경우가 있습니다 (교차 판정의 유일한 불일치 사례가 이 경우였음).
- 관련 기사가 있는 질의가 77건으로 표본이 크지 않습니다.
- LLM 판정 교차 검증은 사람이 아닌 이종 LLM 간 비교입니다.
